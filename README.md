## Deployment

### Podman Compose

```yaml
services:
  beszel:
    image: "ghcr.io/daemonless/beszel:latest"
    container_name: beszel
    environment:
      - PUID=1000  # User ID for the application process
      - PGID=1000  # Group ID for the application process
      - TZ=UTC  # Timezone for the container
      # - APP_URL=  # Public URL of the hub (used in alert/email links and subpath routing)
      # - DISABLE_PASSWORD_AUTH=  # Disable password login (for OAuth2/OIDC-only setups)
      # - USER_CREATION=  # Allow creating additional user accounts via OAuth2/OIDC
      # - SHARE_ALL_SYSTEMS=  # Share all monitored systems across all users
      # - AGENT_LISTEN=  # Optional separate address/port (for example :45876) for agent-only WebSocket connections
      # - CHECK_UPDATES=  # Check GitHub for newer Beszel releases (defaults to false)
      # - CSP=  # Optional Content-Security-Policy response header value
      # - HEARTBEAT_URL=  # External URL to ping periodically for hub heartbeat monitoring
      # - AUTO_LOGIN=  # Email address of a user to automatically sign in
    volumes:
      - "/containers/beszel:/config"
    ports:
      - "8090:8090"
    # always (not unless-stopped) so FreeBSD's podman rc.d auto-starts it at boot
    restart: always
```

Save as `compose.yaml`, then run `podman-compose up -d`.

Save the files above, then run `appjail-director up`.


> [!WARNING]
> Exposing ports in AppJail means that your service can be reached from remote hosts. If that is not your intention, do not expose the ports and communicate with the service using the jail's IPv4 address or hostname assigned by the virtual network.
>
> To avoid exposing ports, just remove the `expose` option in your `appjail-director.yml` or from your command-line arguments.

## First start and data

Open `http://<host>:8090` to create the initial admin account. Persistent
PocketBase SQLite data, the generated SSH key (`id_ed25519`), and backups
live in `/config/beszel_data`.

## Connecting FreeBSD hosts

Install `beszel-agent` natively on each FreeBSD host
(`beszel-agent_freebsd_amd64.tar.gz` or `beszel-agent_freebsd_arm64.tar.gz`
from upstream releases) so the agent has direct access to host CPU, ZFS,
disk, temperature, and container metrics, then add the system in the hub
UI.

## CLI subcommands

Run Beszel/PocketBase CLI commands as `bsd` in `/config`, for example:

```sh
podman exec beszel beszel superuser upsert admin@example.com <password>
```


**Architectures:** amd64
**User:** `bsd` (UID/GID via PUID/PGID, defaults to 1000:1000)
**Base:** FreeBSD 15.1
